# AgentLens M5 — 规则式循环检测

前提：以独立验收的 M4 为基线。只实现 PROJECT.md 的 M5：基于已存储的 AgentEvent 检测可能的重复工具、重复文件、重复错误、工具往返与无进展循环。保持本地只读、Apache-2.0、Node `>=22.13`。不做 M6 Provider 适配、Replay、UI、云服务或 LLM 判断。

交付：给现有 `inspect <run-id>` 增加清晰的“Possible loops”诊断区，并提供可测试的纯规则检测入口。每条信号说明规则、触发证据（事件范围、工具/文件/错误及次数）与置信边界；无命中明确说明。检测必须使用实际事件输入与结果，不把工具正常重复或一次失败直接断言为循环；无法从载荷判定进展时明确表示无法判定。规则和阈值写入 README，输出确定、有限，较大运行也不应无界输出。

验收：用现有 `loop-read-pingpong.json` 和 `loop-grep-repeat.json` fixture 证明对应命中及证据；再覆盖相同工具但输入变化、错误后成功恢复、正常编辑后重试、单次调用及运行中未结束工具等反例，验证不会误报为已确认循环。重复输出稳定，事件顺序保持，数据库 SHA-256/mtime 不变；缺失/损坏/未来版本 DB 和未知 Run 错误不退化。全新安装后 lint/test/build、构建产物 CLI `inspect` 端到端、Ubuntu Node 22/24 CI 通过。

在已授权仓库的 `devin/m5-loop-rules` 分支提交并推送，报告完整 SHA、实际命令/结果、规则阈值、误报/漏报边界。完成 M5 后停下等待独立验收；不直接修改 main，不开始 M6。计算消耗上限 10 ACU；接近上限时停止并报告进度。
