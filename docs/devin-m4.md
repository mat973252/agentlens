# AgentLens M4 — 两次运行对比

前提：以独立验收的 M3 为基线。只实现 `agentlens diff <runA> <runB>`，使用现有本地 SQLite、Run/Event Schema 和只读打开方式。保持 Apache-2.0、Node `>=22.13`。不做 M5 循环检测、Provider 适配、Replay、UI、云服务或 LLM 判断。

目标：开发者对比同一数据库中一次成功 Run 与一次失败 Run，能从简洁文本中快速发现主要行为差异。至少展示：

- 概览：两个 Run ID/状态、duration、input/output/reasoning tokens（存在时）、toolCalls/failedToolCalls；分别给出 A、B 与可计算的变化。缺失指标明确显示未知，不填零或推断。
- 工具分布：按工具名汇总两次运行的调用次数及差值，排序稳定；从事件记录统计，并清楚处理未结束的工具调用。
- 错误与结果：分别列出有代表性的错误/失败数量及最终结果差异；避免把文本相同但来源不同的错误误称为同一根因。
- 时间线差异：提供可读、确定性的关键事件对照，使用户看出两次运行在何处或何种行为上不同；说明匹配规则，不作未经证实的语义推断。

CLI 支持与 `runs`/`inspect` 一致的 `--db` 路径。数据库只读，不创建缺失文件、不改记录、不触发迁移。未知 Run、相同 Run ID、缺失/损坏/不支持的数据库给出明确错误；同一输入重复输出一致。更新帮助与 README，只描述已实现能力。

验收：从 M1 fixture 中选择至少一组成功/失败 Run，另以两个行为差异明显的 Run 验证工具分布、错误与时间线；实际运行构建产物 CLI，人工从输出定位主要差异并记录所用时间/观察，不把单人单样本当作达到“30 秒内理解”产品指标的证明。核对无数据时的未知指标、事件顺序、结果、只读 SHA-256/mtime 及错误路径。全新安装后 lint/test/build 和 Ubuntu Node 22/24 CI 通过。

在已授权仓库的 `devin/m4-diff` 分支提交并推送，报告完整 SHA、实际命令/结果和已知限制。完成 M4 后停下等待独立验收；不直接修改 main，不开始 M5。计算消耗上限 10 ACU；接近上限时停止并报告进度。
